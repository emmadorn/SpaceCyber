NOS3 Directories
General Definitions
  • F' (F Prime): Flight spftware framework designed for developing embedded systems on spacecraft, responsible for onboard oeprations
  • COSMOS: Open source ground system software by Ball Aerospace, provides command and control of flight software
  • 42: OPen source visualization and simulation tool for spacecraft attitude and orbital dynamics, used to provide dynamic enironmental data
  • fsw: Directories contain things for cFS ("flight software")
  • gsw: Directories contain things for COSMOS ("ground software")
The following are directories:
  1. Components
    1. arducam: contains ArduCam cFS app (simulates camera functionality for interfacing with CubeSats or small satellites, allows for testing image capture, processing, and communication)
    2. cryptolib: provides software-only solution using CCSDS Space Data Link Security Protocol - Extended Procedures (SDLS-EP) to secure communications between a spacecraft running cFS and a ground station
    3. generic_adcs: Attitude Determination and Control System (simulates sensors determining the orientation of the satellite in space)
    4. generic_css: I2C device (Inter-Integrated Circuit, a synchronous serial communication protocol), accepts multiple commands including requests for telemetry
    5. generic_eps: Electrical Power System, I2C device that accepts commands to switch state, request telemetry and reset the spacecraft
    6. generic_fss: Fine Sun Sensor, SPI (Serial Peripheral Interface) device that accepts commands to retrieve sun angles and returns sun angles and an error code
    7. generic_imu: Inertial Measurement Unit, CAN (Controller Area Network) device that responds to requests for telemetry and data
    8. generic_mag: SPI device accepting multiple commands which include requests for telemetry
    9. generic_radio: socket based device accepting multiple commands which include requests for telemetry and data
    10. generic_reaction_wheel: contains generic reaction wheel cFS app
    11. generic_star_tracker: UART (Universal Asynchronous Receiver-Transmitter) device accepting multiple commands including requests for telemetry and data
    12. generic_thruster: UART device used to enable the thrusters, setting them to a percent of a full thrust
    13. generic_torquer: device that accepts as input a current (% of the max) and returns value of generated magnetic field
    14. novatel_oem615: NovAtel OEM 615 cFS app, USART (Universal Synchronous-Asynchronous Receiver-Transmitter) device accepting multiple
    15. sample: contains template component for integrating new components in NOS3
    16. syn: provides executable SYNOPSIS example for the user (a library with 8 sets of data modified by user)
  2. FSW - Repositories needed to configure cFS for NOS3
    1. cf: CFDP application, provides CFDP (CCSDS File Delivery Protocol) CCSDS 727.0-B-5 compliant services, provides file receive and transmit functionality to this protocol
    2. ci: Command Ingest, responsible for receiving commands from external source (like a ground station) over a transport channel, and forwards command to appropriate application over the software bus (SB)
    3. ci_lab: Command Ingest Lab, simple command uplink app that accepts CCSDS telecommand packets over a UDP/IP port (does not provide full CCSDS Telecommand stack implementation)
    4. ds: Data Storage app, stores SB messages in files, generally stored on a storage device as a solid state recorder but could be stored on any file system
    5. fm: File Manager app, provides onboard file system management services by processing ground command for copying, moving and renaming files, decompressing files, creating directories, deleting files and directories, providing file and directory informational telemetry messages, as well as open file and directory listings
    6. hwlib: Hardware library, provides abstraction layer for hardware interfaces across platforms (i.e. linux and nos-linux)
    7. io_lib: Input/Output library, collection of protocol libraries to be called by the CI/TO application custom implementations
    8. lc: Limit Checker, monitors telemetry data points and compares the values against predefined threshold limits; when a threshold condition is encountered, event message is issued and a Relative Time Sequence (RTS) command script may be initiated to respond to the violation
    9. sc: Stored Command app, allows system to be autonomously commanded using sequences of commands that are loaded to it, supports both Absolute Time tagged command Sequences (ATSs) and Relative Time tagged command Sequences (RTSs)
    10. sch: Scheduler, provides method of generating software bus messages at pre-determined timing intervals
    11. to: Telemetry Output, responsible for transmitting telemetry to external destinations over transport devices
    12. to_lab: Telemetry Output lab, simple telemetry downlink app that sends CCSDS telecommand packets over a UDP/IP port
    13. cfe: Contains NASA’s Core Flight Executive, a collection of services and associated framework to be located in the cfe subdirectory of a cFS Mission Tree
    14. osal: Contains NASA’s Operating System Abstraction Layer (OSAL), a collection of abstraction APIs and associated framework to be located in osal subdirectory of a cFS Mission Tree
    15. psp: Platform Support Package (PSP), collection of APIs abstracting platform specific functionality to be located in psp subdirectory of a cFS Mission Tree
    16. elf2cfetbl: ELF to cFE Table Converter Tool, converts ELF to cFE binary tables for cFS
  3. GSW - NOS3 ground station files and other ground-based tool (related to COSMOS)
    1. OrbitInviewPowerPrediction: Orbit Inview and Power Prediction Tool, README file states to look through the code for learning what the latest OIPP does
    2. cosmos: SmallSAT COSMOS Database, used for capturing command and telemetry definitions, testing procedures/scripts, and operational scripts
  4. SIMS
    1. nos_time_driver: NOS Engine Time Driver, making sure different components are synchronized when running simulations to ensure realism
    2. sim_common: contains shared files and utilities used for multiple simulation components (i.e. libraries, base models, configurations)
    3. sim_terminal: tools/interfaces for interacting with simulations (i.e. logging, command inputs, or telemetry outputs)
    4. truth_42_sim: simulator to connect to 42 and provide packed telemetry to COSMOS, streams data to COSMOS and lets data be read in COSMOS, meant to reflect satellite’s real-world dynamics with data to validate simulations
