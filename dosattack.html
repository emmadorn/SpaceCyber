Denial of Service Attack on the Software Bus
This attack's purpose is to stop other applications from receiving any and all commands through the software bus the same way denial of service attacks work on the internet. These attacks would be more vulnerable on satellites because of how they work if they don't take proper security measures.
The Core Flight System (cFS) Software Bus Network (SBN) application facilitates communication and data exchange between various software components within a spacecraft. It functions as a central messaging hub, enabling components to publish and subscribe to messages without direct knowledge of each other's location or implementation details. The SBN utilizes a publish-subscribe model, where components can publish messages to specific topics, and other components can subscribe to those topics to receive relevant messages. The SBN ensures reliable message delivery through a combination of buffering, acknowledgments, and retransmission mechanisms. Components interact with the SBN using a well-defined API, which simplifies the integration of new components into the system. By providing a flexible and efficient communication framework, the SBN plays a crucial role in enabling complex spacecraft systems to operate seamlessly.

2. Flood one important pipe with messages
This attack uses the same code with slight adjustments. Instead of iterating through all the message ID’s we target a specific ID, in this case the houseKeeping message ID. We then proceed to continuously send messages on this pipe forcing the software bus to discard the oldest message on the queue without processing it completing the attack.

Some specifications we want to note is that the pipe depth has to be considered. Pipe depth determines how many messages can be on a pipe at a time. Overwhelming pipes with a large pipe depth can be more challenging and require more resources.
